# AI Governance & Compliance Policy

## Overview

COMPLYOS AI Compliance Assistant provides intelligent assistance for tax compliance workflows. This document outlines governance measures, privacy protections, and operational guidelines.

## Privacy & Data Protection

### Sensitive Data Handling

The AI system **NEVER** sends raw sensitive data to external AI providers. All prompts are pre-processed to remove:

- **PAN Numbers**: 10-character alphanumeric (e.g., ABCDE1234F)
- **GSTIN**: 15-character format (e.g., 27AAAAA0000A1ZA)
- **Aadhaar Numbers**: 12-digit numbers
- **Bank Account Numbers**: 9-18 digit sequences
- **Mobile Numbers**: 10-digit Indian mobile numbers

### Redaction Implementation

```typescript
// Example: redactSensitiveData function in ai-compliance.service.ts
function redactSensitiveData(text: string): string {
  let redacted = text.replace(/[A-Z]{10}[0-9]{3}[A-Z]/gi, '[PAN_REDACTED]');
  redacted = redacted.replace(/[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z]{1}[0-9]{1}[A-Z]{1}[0-9A-Z]{1}/gi, '[GSTIN_REDACTED]');
  redacted = redacted.replace(/\b\d{12}\b/g, '[AADHAAR_REDACTED]');
  redacted = redacted.replace(/\b\d{9,18}\b/g, '[ACCOUNT_REDACTED]');
  return redacted;
}
```

### Data Minimization

- Only relevant compliance fields are sent to AI
- Business identifiers are truncated or hashed
- No PII beyond what is strictly necessary for context

## Human Review Required

### Critical Decision Points

AI assistance in COMPLYOS is **advisory only**. All AI-generated outputs must be reviewed by a qualified CA before:

1. **Filing any response** - AI summaries must be verified against official notice
2. **Calculating tax liability** - Verify demand amounts, interest calculations
3. **Meeting deadlines** - Confirm response dates with official communications
4. **Advising clients** - Ensure recommendations align with current law

### AI Disclaimer

```
⚠️ AI-Generated Content - Requires Human Review

This analysis was generated by AI and is intended for assistance only.
All information must be verified against official notices and current
regulations before taking any compliance action.

Consult a qualified CA for complex matters.
```

## Audit Logging

### AIActionLog Entity

Every AI interaction is logged with:

```typescript
interface AIActionLog {
  id: string
  tenantId: string
  workspaceId?: string
  userId: string
  promptType: AIPromptType  // NOTICE_SUMMARIZE, TASK_SUGGEST, etc.
  entityType: AIEntityType  // NOTICE, TASK, DOCUMENT, etc.
  entityId?: string
  provider: string          // openai, local, mock
  modelUsed?: string
  promptTokens?: number
  completionTokens?: number
  totalTokens?: number
  executionTimeMs?: number
  prompt?: string          // Truncated, redacted
  response?: string         // Truncated
  errorMessage?: string
  success: boolean
  correlationId?: string
  createdAt: DateTime
}
```

### Log Retention

- Logs are retained for **2 years** minimum
- Tenant-scoped queries only
- No cross-tenant data access

## AI Feature Flags

### Configuration

```bash
# Enable/disable AI features globally
ENABLE_AI_FEATURES=true|false

# Provider selection
AI_PROVIDER=openai|local|mock

# OpenAI configuration
OPENAI_API_KEY=sk-...

# Local model (Ollama) configuration
AI_LOCAL_ENDPOINT=http://localhost:11434
AI_MODEL=llama3

# Model selection
AI_MODEL=gpt-4-turbo-preview
```

### Feature Flag States

| Flag Value | Behavior |
|------------|----------|
| `true` | AI enabled, uses configured provider |
| `false` | AI disabled, mock responses only |
| `mock` | Demo mode, returns simulated responses |

## AI Limitations

### Current Scope (v1.0)

✅ **Enabled**:
- Notice summarization and analysis
- Compliance task recommendations
- Dashboard risk insights
- Document category suggestions

❌ **Not Enabled**:
- Autonomous filing actions
- OCR document processing
- Vector search / embeddings
- Agent loops / multi-step tasks
- Real-time regulatory updates

### Known Limitations

1. **Model Knowledge Cutoff**: AI knowledge may not reflect latest amendments
2. **Context Length**: Long notices may be truncated
3. **Format Variability**: Government notices vary in structure
4. **Language**: Optimized for English; Hindi notices may need translation

## Provider Abstraction

The AI system uses a provider-agnostic architecture:

```
┌─────────────────────────────────────────┐
│           AIComplianceService            │
│  (Workflow logic, prompts, logging)     │
└─────────────────────────────────────────┘
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
┌───────────────┐       ┌───────────────┐
│ OpenAI Provider│       │ Local Provider │
│ (GPT-4)       │       │ (Ollama/Llama) │
└───────────────┘       └───────────────┘
        │                       │
        └───────────┬───────────┘
                    ▼
          ┌─────────────────┐
          │ Mock Provider   │
          │ (Demo/Fallback) │
          └─────────────────┘
```

### Adding New Providers

1. Implement `IAIModel` interface
2. Add provider to `AIProviderService.createProvider()`
3. Add configuration keys to environment

## Security Measures

### API Key Handling

- API keys stored in environment variables only
- Keys never logged or displayed
- Keys never sent to non-OpenAI endpoints

### Rate Limiting

- Token limits enforced per tenant
- Request queuing for batch operations
- Timeout handling with graceful degradation

### Input Validation

- All prompts sanitized before sending
- Maximum token limits enforced
- Response validation before storage

## Compliance Categories

### Allowed Use Cases

| Category | Description | Risk Level |
|----------|-------------|------------|
| Notice Summarization | Extract key info from notices | LOW |
| Task Recommendations | Suggest compliance actions | MEDIUM |
| Risk Insights | Dashboard analytics | LOW |
| Document Tagging | Auto-classify documents | LOW |

### Prohibited Use Cases

- Generating legal advice without review
- Filing returns automatically
- Making regulatory interpretations
- Sending client data externally without consent

## Error Handling

### Failure Modes

| Scenario | Behavior |
|----------|----------|
| API timeout | Log error, return mock response |
| Invalid API key | Return error, disable provider |
| Rate limit exceeded | Queue requests, retry with backoff |
| Malformed response | Log error, return partial data |

### Graceful Degradation

When AI features fail:
1. Log the failure with full context
2. Return mock/demo response
3. Notify user of fallback mode
4. Continue without blocking user

## Best Practices

### For CA Firms

1. **Always review** AI-generated summaries before advising clients
2. **Verify deadlines** against official notice documents
3. **Document AI usage** in client engagement records
4. **Stay updated** on regulatory changes AI may not reflect

### For System Administrators

1. **Monitor token usage** and costs
2. **Review audit logs** periodically
3. **Update models** when new versions available
4. **Test fallback modes** regularly
